# v0.2.0

## Floating images: sheet_images

A new tool, `sheet_images`, puts images over the grid, each anchored to a
cell, then lists, moves and deletes them. An agent building a table of
evidence can put a screenshot beside each row. With mcp-piper, each file is
sent as `"@file64:/abs/path.png"`, so its bytes never pass through the
agent's context.

- PNG, JPEG and GIF, told apart by their first bytes; anything else is refused.
- Over 2 MiB or 1,048,576 pixels, the server downscales the image and says so.
  Keep files under about 3 MB: a larger request is refused before the tool runs.
- Each inserted image gets an id that lasts, `gsheet-mcp:<token>`. Images put
  there another way are listed with an id from their position.
- `delete` previews first and removes only with `dry_run=false`.

The Sheets API cannot create or move these images, so the tool runs a small
Apps Script project of the server's own. Whoever runs a server sets it up
once, as in `docs/deploy.md`, and sets `GSHEET_MCP_APPS_SCRIPT_ID`. Without
it, `sheet_images` says it is not configured and every other tool is
unchanged. No new permission is asked for, so nobody signs in again; a
connected client sees the new tool after it reconnects once.

## render_range can save to disk

The `render_range` description now tells agents that with mcp-piper,
`"_save_to": "/abs/dir/"` saves the page images to disk instead of reading
them.

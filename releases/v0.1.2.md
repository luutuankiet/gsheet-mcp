# v0.1.2

## Fixes from testing against live sheets

Pulls and queries: `query_range` checks the result size before it reads, a
pull into an empty cache scans the sheet first, and `gsheet push` reports a
missing `.sql` file as file not found. Landing a CSV keeps plain decimals as
numbers and the receipt reads back in the same notation as `read_range`.

Writes: `write_cells` takes typed values and refuses a write over 50,000
cells. Receipts name merges by their range and list row and column size
changes, and a write into a hidden row or column warns. When the stale-write
guard refuses, it says what changed, such as a format change. Its reads are
bounded, so a large target no longer reads the whole tab.

Scripts: a script error points at the line in your script, not the wrapper.
Tab names in quotes are read ahead of time, and the apply hint is complete.
Raw requests with an unknown kind or `sheetId` are refused when the plan is
made, and errors name the request by your own index.

## A failed apply keeps its plan

When an apply fails before anything is written, the plan stays valid and can
be applied again. When it fails after part of the write landed, the plan is
gone and a retry is refused, because what was written is unknown: re-read the
cells and make a new plan. Two applies of the same plan at once cannot both
run.

## scan_sheet lists pivot tables and chart sources

The scan now shows each pivot table with its source range, and up to six
source ranges per chart.
